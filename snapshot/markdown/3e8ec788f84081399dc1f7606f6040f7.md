To connect to the robot over wifi, you will need to use Android Debug Bridge (ADB). This is a command-line tool packaged with Android Studio.
1. Make sure Android Studio Platforms Tools is installed.
	- In Android Studio click **Tools** \>\> **SDK Manager**
	- Go to the **SDK Tools** tab
	- Make sure that **Android SDK Platform-Tools** is checked
	- Click **Apply** then **OK**
2. Make the **adb** command available from any directory.
	- Open the Terminal in Android Studio.
	- Paste the following command to add adb to your command line: `printf '\n# The next line enables Android Debug Bridge to run from any directory\nexport PATH=$PATH:$HOME/Library/Android/sdk/platform-tools\n' >> ~/.zshrc`
	- If you see an error, you need to see Tech to make sure you have the permissions to write to your z-shell profile
	- Run `source ~/.zshrc` or close and reopen Terminal to make the adb commands available. 
3. Confirm **adb** is accessible.
	- In the Terminal run `adb version`
	- You should see some info and not an error message. If you see an error make sure you have followed the steps above. You may need to see tech for help.
4. Connect to the Robot Controller
	- Join the Robot Controller's WiFi
	- In Android Studio's Terminal run: `adb connect 192.168.43.1:5555`
	- You should get the response: `connected to 192.168.43.1:5555`
5. At the top of the screen, click the devices menu and select the Robot Controller
6. Now you can click Run to load your code onto the Robot Controller.
### Connection Issues?
Most connection issues happen when you switch your wifi off of the robot wifi without running `adb disconnect` first. Try to remember to run `adb disconnect` before you switch off the robot's wifi.
If you are connecting/disconnecting from the robot during a session **adb** sometimes has trouble keeping up. If you are unable to connect or are getting a message that you are already connected (even though you're not), here's what to do:
- In your Android Studio Terminal run `adb disconnect`
- Then run `adb devices` to confirm no devices are connected
- Finally run `adb connect 192.168.43.1:5555`
Still having issues?
- Run `adb kill-server`
- Then run `adb start-server`
- Finally try `adb connect 192.168.43.1:5555` again
### Errors with Building the Code?
The most common error we see is that Android Studio Gradle tries to download library files from the internet while you are connected to the robot's wifi. This obviously won't work. We need to download all of those files and cache them so that we can build the project while connected to the Robot Controller. Here's how:
- Connect to the Internet (<span underline="true">**not**</span> the Robot Controller wifi)
- Open the Gradle Panel on the right side of your screen (the elephant icon)
- Then **toggle offline mode OFF** using the offline mode icon (when on, the background is shaded, then off the background is black)
- Sync the project: go to **File \>\> Sync Project with Gradle Files**
- Rebuild the project using the downloaded libraries: **Build \>\> Clean and Assemble Project with Tests**
- Now **toggle offline mode ON** using the offline mode icon
- Connect to the Robot Controller wifi.
- In the Terminal run `adb connect 192.168.43.1:5555` to connect Android Studio to the robot
- Run your TeamCode
### Install the Panels Utility
In the competition, you need to run your robot from a Driver Hub, but for code testing, it is easier to run code from your computer using Panels. This takes a few minutes to install, but will save hours of debugging time.
1. Make sure your robot is connected to the internet (not the robot Wi-Fi).
2. In the left sidebar open **Gradle Scripts \>\> build.gradle (Module :Teamcode).  **Add the green highlighted lines.
	```javascript
android {
    namespace = 'org.firstinspires.ftc.teamcode'
 
    compileSdk = 35
    defaultConfig {
        minSdk = 24
    }
 
    packagingOptions {
        jniLibs.useLegacyPackaging = true
    }
}

dependencies {
    implementation project(':FtcRobotController')
    implementation "com.bylazar:fullpanels:1.0.13"
}
	```
	<callout icon="💡" color="gray_bg">
		What's a Gradle script? Gradle scripts are scripts that are run when the Java project is compiled. In this case we will add to the script that tells Android Studio to download additional code from the internet and install it in our project.
	</callout>
3. In the left sidebar open **Gradle Scripts \>\> build.gradle (Project :FTCRobotController).  **Add the green highlighted code.  Make sure you paste it inside **`allprojects`** **NOT** `buildscripts`.
	```javascript
allprojects {
    repositories {
        mavenCentral()
        google()
        maven {
            url = "https://mymaven.bylazar.com/releases"
        }
    }
}
	```
4. Go to **File \>\> Sync Project with Gradle Files**.  To download the Panels code into your project.
5. Save the file (File \>\> Save All or `⌘` S)
6. Click the **Assemble** button (the hammer) in the top task bar. This will build the project and download any needed files.
7. Open the Build panel by clicking the hammer icon on the bottom left of the screen and open the Build Output tab.  When the build process is complete you should see a message that says `BUILD SUCCESSFUL in 47s`.
### Upload Code to the Robot
For FTC Dashboard to work, it needs to be uploaded to the robot along with your code
1. Make sure your computer is connected to the robot's Wi-Fi network.
2. In the Terminal run `adb connect 192.168.43.1:5555` to connect Android Studio to the robot
3. Click the **Run** button in the top task bar to upload the code onto the robot.
	- The LED on the Control Hun will flash blue as the code is uploaded and then turn solid green when the robot has restarted.
### Open Panels
1. Make sure your computer is connected to the robot's Wi-Fi network.
2. Make sure the robot is powered on and showing a solid green LED.
3. In the Chrome browser navigate to `http://192.168.43.1:8001`
You wont see much on the the Panels website yet, but there may be some OpModes to select in the drop down menu. These OpModes are from the Blocks or OnBot programming platforms.
