### Set-up your TeamCode Folders
As we build up to competition time you will be writing a number of Java programs in the **TeamCode** module of your Android Studio project. To help all of our teams communicate and help each other, we try to use a common folder structure. Before you write an OpMode, get yourself organized.
1. In Android Studio, in the left sidebar navigate to **TeamCode \>\> java \>\> org.firstinspires.ftc.teamcode**
2. Right click (control + click) on **org.firstinspires.ftc.teamcode**
3. Select **New \>\> Package**
4. In the New Package dialogue box type: `org.firstinspires.ftc.teamcode.auto`
	- This creates a package (aka folder) named **auto** inside the **teamcode** package
5. Add another package named `org.firstinspires.ftc.teamcode.teleop`
6. Add another package named `org.firstinspires.ftc.teamcode.hardware`
These three folders will hold your **auto**nomous and driver controlled (**teleop**) OpModes as well as a collection of classes that interact with different pieces of **hardware** (motors, sensors, etc.)

### Refine your `drive` method
In FTCSIM your drive method used "ticks" to drive. For our real robots, we want to use real units of measurement. In this section you will fix your drive method to use centimeters instead of ticks.
1. Change the definition of your `drive` method from `public void drive(double speed, int ticks)` to:
	- `public void drive(double speed, double distance)`
2. We will need a constant factor to convert from centimeters to a number of ticks to use with the `setTargetPosition(ticks)` method. In Java we define constants at the top of the class. Under the lines where you initialize the motor variables `DcMotor BR;` add the following line:
	- `public static double TICKS_PER_CM = 100.0;`
		- `public static` tells Java that this variable can be accessed outside of this class. You will use this to tune the variable in FTC Dashboard.
		- `double` tells Java to expect a decimal number
		- `TICKS_PER_CM` is the name of the variable
3. To use this `TICKS_PER_CM` variable in your `drive()`method add the following line at the top of the drive method.
	- `int ticks = (int) (distance * TICKS_PER_CM);`
	- To be used by `setTargetPosition()`, ticks must be an integer, not a decimal (double). The `(int)` before the expression converts the result of `distance * TICKS_PER_CM` to an integer.
4. Inside the `runOpMode()` method call the drive method with a reasonable distance. For example:
	- `drive(0.2, 100)`
	- Which should drive slowly, 100 cm, if you get the constant TICKS_PER_CM right.
5. Upload your code and open the FTC Dashboard. You should see your OpMode in the Configuration panel where you should be able to adjust the value of TICKS_PER_CM. As you adjust the value make sure to click the save button.
6. Run your OpMode and measure how far the robot goes. Adjust the value of `TICKS_PER_CM` in the Dashboard until it is driving the right distance. Then you can update the value of `TICKS_PER_CM` in the actual code.
