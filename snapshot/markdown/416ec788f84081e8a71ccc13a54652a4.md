## Why Log Data?
Telemetry on the Driver Station shows you a number which is updated dozens of times per second. That is useful for debugging, but it is a poor tool for understanding motion.  A controller's behavior happens over time: the mechanism accelerates toward the target, passes it, swings back, and settles. By the time you read the number on the screen, it has changed ten times.
<span color="red">**`Data logging`**</span> means recording values on every pass through the loop so you can look at how they change over time. A <span color="red">**`time series graph`**</span> of those values turns "it kind of wobbles" into evidence: how far it overshot, how long it took to settle, and whether it ever actually reached the target.
## What Is Panels?
<span color="red">**`Panels`**</span> is a free, open-source dashboard for FTC robots. It runs on the Control Hub and serves a web page you open in a browser on a laptop connected to the robot's Wi-Fi. Panels can start and stop OpModes, show telemetry, draw the robot on a field, tune variables live, and, graph numeric telemetry values over time.
Panels is the dashboard used by Pedro Pathing, so some teams already have it installed. If your team uses FTC Dashboard instead, the same ideas apply, but the code below is specific to Panels.
## Step 1: Install Panels
<callout icon="⚠️" color="gray_bg">
	**Coordinate with your team first**
	Adding a library changes the build for everyone on your team. Talk to your software lead, do this on a branch, and make sure the project still builds and deploys before you merge.
</callout>
Panels is added to the FTC project through Gradle, the tool Android Studio uses to download libraries and build your code.
1. In Android Studio, open `build.dependencies.gradle` (in the root of the FtcRobotController project).
2. Inside the `repositories { }` block, add the two Maven repositories Panels needs:
	```groovy
repositories {
    // ...existing repositories...
    maven { url = 'https://mymaven.bylazar.com/releases' }
    maven { url = 'https://repo.dairy.foundation/releases' }
}
	```
3. Inside the `dependencies { }` block, add Panels:
	```groovy
dependencies {
    // ...existing dependencies...
    implementation 'com.bylazar:fullpanels:1.0.20'
}
	```
4. Click **Sync Now** in the bar at the top of the editor, then build and deploy to the robot as usual.
	<callout icon="💡" color="gray_bg">
		**Version numbers**
		Check the [Panels docs](https://panels.bylazar.com/docs/com.bylazar.docs) for the current version. Robots on FTC SDK 12 need Panels 1.0.15 or newer.
	</callout>
## Step 2: Open Panels
1. Run any OpMode on the robot, or just power it on.
2. Connect your laptop to the robot's Wi-Fi network (the same network the Driver Station uses).
3. In a browser, go to `http://192.168.43.1:8001`
You should see the Panels dashboard. If the page doesn't load, confirm you are on the robot's network and that the code you deployed includes Panels.
## Step 3: Send Data to Panels
Panels graphs numeric values that you send through its telemetry manager. In your OpMode, create a `TelemetryManager`, add data to it every loop, and call `update()`.
```java
import com.bylazar.telemetry.PanelsTelemetry;
import com.bylazar.telemetry.TelemetryManager;

// Create the Panels telemetry manager once, in init()
TelemetryManager panelsTelemetry = PanelsTelemetry.INSTANCE.getTelemetry();

// Panels sends data every 75 ms by default. A shorter interval gives
// the graph more points, which helps with fast motions like a
// flywheel spinning up. Value is in milliseconds.
panelsTelemetry.setUpdateInterval(20);

// Alternatively create a single joined telemetry object that sends data to both Panels and the Driver Station
Telemetry joinedTelemetry = new JoinedTelemetry(PanelsTelemetry.INSTANCE.getFtcTelemetry(), telemetry);

// Every loop, add the values you want to graph
panelsTelemetry.addData("target", target);
panelsTelemetry.addData("currentValue", currentValue);

// Send to Panels AND the Driver Station
panelsTelemetry.update(telemetry);
```
- **How the Graph finds your data.** 
	The Graph reads telemetry lines in the format `name:number`. Each `addData("target", target)` produces one of those lines.
- **Use the same label every loop.**
	The label (`"target"`, `"currentValue"`) is the name of the line on the graph. If the label changes, you get a new line.
- **Only numbers can be graphed.** Send numbers as numbers, not formatted strings like you might for Drivers Station telemetry..
