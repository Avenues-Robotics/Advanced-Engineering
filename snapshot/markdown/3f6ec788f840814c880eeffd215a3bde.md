### What Are Git and GitHub?
Git is a **version control system** for coders.  If you have used Google Docs, you have already used version control. Google Docs saves your document every few seconds, and **File \>\> Version history** lets you go back to any earlier version. **Git** does the same job for code, with one big difference: Git does not save versions automatically. You decide when your code has reached a point worth saving, and you save a snapshot called a **commit**, along with a short message describing what changed.
That sounds like extra work, but it makes the history far more useful. Instead of thousands of autosaves labeled only with a time, you get a clean list of meaningful checkpoints, like "Drive straight 100 cm working" or "Add color sensor to Drive class." When something breaks, you can see exactly what changed since the last version that worked, and go back to it if you need to.
**Git** and **GitHub** are two different things:
- **Git** is the program on your laptop that tracks changes and stores your commits. You installed it in <mention-page url="https://app.notion.com/p/3e8ec788f8408186a69fc23ff76868d7"/> where you **cloned** the FTCRobotController code from the official first **repository**.
- **GitHub** is a website that stores a copy of your project and its full history online. In Google Docs, your history lives in the cloud automatically. With Git, your history lives on your laptop until you **push** it to GitHub. Pushing backs up your work and lets your teammates **pull** it onto their own computers.

### What You Will Do in This Tutorial
Right now your Android Studio project lives in one place: your laptop. If your laptop dies, your code is gone, and nobody on your team can see what you wrote. In this tutorial you will connect Android Studio to GitHub, create your own **repository** in the Avenues Robotics organization, and upload your project to it.
A few terms you will use from here on:
- **Repository (repo):** a project folder tracked by Git, including the full history of every change.
- **Commit:** a saved snapshot of your changes, with a message describing what changed. Commits are saved on your laptop.
- **Remote:** a copy of the repository hosted somewhere else, like GitHub.
- **Push:** uploading your commits from your laptop to a remote.
- **Pull**: downloading the current remote version of the project to your computer

### Sign in to GitHub from Android Studio
1. Open Android Studio's settings: **Android Studio \>\> Settings...** (`⌘,`)
2. In the left sidebar, go to **Version Control \>\> GitHub**
3. Click the **+** button and choose **Log In via GitHub...**
4. A browser window opens. Sign in to GitHub if asked.
5. On the page that asks you to authorize **JetBrains IDE Integration**, click the green **Authorize** button, then return to Android Studio.
6. Your GitHub account should now appear in the list. Click **OK**.
<callout icon="💡" color="gray_bg">
	Android Studio saves a secure sign-in token, so you never type your GitHub password into Android Studio. It uses this token every time you push.
</callout>
### Create Your Repository in the Avenues Robotics Organization
1. In your browser, go to [github.com/Avenues-Robotics](https://github.com/Avenues-Robotics)
2. Click the **+** menu in the top right corner and choose **New repository**
3. Set the **Owner** to **Avenues-Robotics** (not your personal username)
4. Name the repository `FirstnameLastname-FTC` using your own name. For example: `JaneDoe-FTC`
5. Set the visibility to **Private**
6. Do **not** add a README, a .gitignore, or a license.
	- Your repository must start completely empty. If GitHub adds any files, it will reject your first push because your laptop doesn't have those files.
7. Click **Create repository**
8. On the next page, copy the **HTTPS** URL. It should look like `https://github.com/Avenues-Robotics/JaneDoe-FTC.git`
### Point Your Project at Your New Repository
When you cloned the FTC SDK in <mention-page url="https://app.notion.com/p/3e8ec788f8408186a69fc23ff76868d7"/>, Git created a remote named `origin` that points to FIRST's repository. You can download from FIRST's repository, but you can't upload to it. You are going to point `origin` at your new repository and add a second remote named `upstream-first` that still points to FIRST, so you can download SDK updates later in the season.
1. In Android Studio, go to **Git \>\> Manage Remotes...**
2. You should see one remote named **origin** with the URL `https://github.com/FIRST-Tech-Challenge/FtcRobotController.git`
3. Select **origin** and click the pencil (edit) icon. Replace the URL with your repository's URL and click **OK**.
4. Click **+** to add a second remote:
	- **Name:** `upstream-first`
	- **URL:** `https://github.com/FIRST-Tech-Challenge/FtcRobotController.git`
	- Click **OK**
5. Click **OK** to close the Manage Remotes window.
6. Double-check your work in the Android Studio Terminal by running `git remote -v`
	- You should see four lines: two for `origin` pointing to your repository, and two for `upstream-first` pointing to FIRST-Tech-Challenge.
### Make Your First Commit
In <mention-page url="https://app.notion.com/p/3e8ec788f84081399dc1f7606f6040f7"/> you edited two `build.gradle` files to install Panels. Git has noticed those changes, but it hasn't saved them yet. A commit saves them.
1. Go to **Git \>\> Commit...** (`⌘` K). The Commit panel opens on the left side of the screen.
2. Under **Changes**, you should see the two `build.gradle` files you edited. Double-click a file to see exactly what changed. Added lines are highlighted in green.
3. Check the box next to each file you want to include in the commit.
	- Only commit changes you meant to make. If you see files you don't recognize (especially under **Unversioned Files**), leave them unchecked and ask a teacher.
4. In the message box, write a short description of what you changed and why. For example: `Add Panels library for telemetry and tuning`
5. Click **Commit** (not Commit and Push, for now).
6. If Android Studio asks for your name and email, enter your name and the email address on your GitHub account, check **Set properties globally**, and continue.
<callout icon="💡" color="gray_bg">
	**Writing good commit messages:** Your commit history is part of your engineering record. A teammate (or future you) should be able to read the list of messages and understand how the code evolved. "Fix stuff" tells nobody anything. "Increase TICKS_PER_CM after measuring a 100 cm test drive" tells the whole story.
</callout>
### Push to GitHub
1. Make sure your laptop is on the internet, <span underline="true">**not**</span> the robot's Wi-Fi.
2. Go to **Git \>\> Push...** (`⇧` `⌘` K)
3. At the top of the Push window, check that your branch is going to **origin**, for example `master → origin : master`
	- If it says `upstream-first` instead of `origin`, click the remote name and choose **origin**.
4. Click **Push**
5. Your first push uploads the entire history of the FTC SDK, so it may take a minute or two. Future pushes are much faster because they only upload your new commits.
6. When the push finishes, a notification in the bottom right corner tells you how many commits were pushed.
### Check Your Work on GitHub
1. Open your repository's URL in the browser (or refresh the page if it is still open).
2. You should see all of the FtcRobotController files.
3. Near the top of the file list, you should see your commit message next to the most recent commit.
4. Click **Commits** to see the full history: thousands of commits from FIRST, with yours on top.
### Your New Routine
From now on, Git is part of how you work:
- **Commit** every time you get something working or reach a good stopping point. Commits are saved on your laptop, so you can commit even while you are connected to the robot's Wi-Fi.
- **Push** at the end of every session, before you close your laptop. Pushing needs the internet, so switch off the robot's Wi-Fi first.
- Once you are comfortable with both steps, the **Commit and Push...** button in the Commit panel does them together.
- If something breaks, your commit history shows exactly what changed since the last time the code worked.
### Troubleshooting
**I don't see Avenues-Robotics in the Owner menu.**
- You may not have accepted your invitation to the organization yet. Check your email or visit [github.com/Avenues-Robotics](http://github.com/Avenues-Robotics). If there is no invitation, ask a teacher.
**Android Studio says "Remote URL test failed," or my push failed with "Repository not found" or a 403 error.**
- First, check that you pasted the correct repository URL in **Git \>\> Manage Remotes...**
- If the URL is right, check that Android Studio is signed in to the correct GitHub account in **Android Studio \>\> Settings... \>\> Version Control \>\> GitHub**, and that you have accepted your invitation to the Avenues Robotics organization. If both look right, ask a teacher.
**My push failed with "permission denied" to FIRST-Tech-Challenge.**
- You pushed to `upstream-first` instead of `origin`. Open **Git \>\> Manage Remotes...** and check that `origin` has your repository's URL. Then push again and make sure the Push window says `origin`.
**My push was rejected with "Updates were rejected" or "fetch first."**
- Your GitHub repository is not empty, probably because a README was added when it was created. Ask a teacher to help you delete it and create a new, empty one.
**The push hangs or times out.**
- You are probably still on the robot's Wi-Fi. Switch to the internet and try again.
**The Terminal asks for my GitHub username and password.**
- Don't push from the Terminal. Use **Git \>\> Push...** from the menu, which uses your Android Studio sign-in.
