Turning your robot using encoders is notoriously inaccurate. Uneven weight distribution, wheel slippage, and collisions with obstacles can all leave the robot short of, or past, the angle you asked for. The encoders only tell you how far the *wheels* turned, not how far the *robot* turned.
The Control Hub has a sensor that can help: the <span color="red">**`IMU`**</span> (inertial measurement unit). An IMU uses a set of sensors to track the orientation of the robot and report its <span color="red">**`yaw`**</span>, <span color="red">**`pitch`**</span>, and <span color="red">**`roll`**</span>:
- **Yaw** is rotation about the vertical axis, like the robot spinning in place. This is also called the robot's **heading**.
- **Pitch** is the front of the robot tipping up or down.
- **Roll** is the robot tipping side to side.
Since a robot normally keeps all four wheels on the ground, the main value you need from the IMU is the yaw. The yaw tells you how many degrees the robot has rotated from the heading it had when the IMU was last reset. IMU readings can also reveal sudden, unexpected forces, like a collision with another robot.

### Learn to Use the IMU
1. Read [IMU in the Robot Controller](https://docs.revrobotics.com/duo-control/sensors/i2c/imu) on the REV Robotics documentation site.
2. Study the code in the **SensorIMUOrthogonal** class in the **external.samples** package in Android Studio. Pay attention to:
	- how the IMU is initialized with the direction the Control Hub's logo and USB ports face on your robot
	- how the yaw angle is read in degrees
	- how the yaw is reset
### Add rotateIMU() to Your Drive Class
Add a new method to your `Drive` class:
```java
public void rotateIMU(double speed, double angle, int direction)
```
- `speed` is the maximum power the motors should use while turning.
- `angle` is how many degrees the robot should rotate.
- `direction` is `1` for counterclockwise rotation or `-1` for clockwise rotation.
The `rotateIMU()` method should use a `PIDF` controller, with the IMU's yaw angle as the measurement. You will also need to initialize the IMU in your `Drive` class's constructor.
<callout icon="💡" color="gray_bg">
	**Things to think about**
	- **How much tolerance is reasonable?** A tolerance that is too tight means the method may never finish. A tolerance that is too loose means your autonomous path drifts. Think carefully about what is acceptable before your method returns.
	- **What happens at 180 degrees?** The IMU reports yaw from -180 to 180 degrees. If the robot starts at 170 and turns 30 degrees counterclockwise, the IMU will read -160, not 200. Make sure your error calculation handles crossing this boundary, or your robot will spin the long way around.
	- **When should the method return?** Like your `drive()` method, `rotateIMU()` should not return until the turn is complete.
</callout>
### Test Your Method
Write a test OpMode that alternates `rotateIMU()` calls with `drive()` calls, for example driving a square. Compare how accurately the robot returns to its starting point using `rotate()` versus `rotateIMU()`.
