The first PID controller you are going to implement will drive a robot toward a barrier and stop it 1 cm from the barrier. You will use a REV 2m Distance Sensor to continuously measure the distance to the barrier. Your PIDF controller will take the current distance and use it to control the drive motors.

</callout>
### Install the Distance Sensor
1. Mount a REV 2m Distance Sensor on the front of your test bot, facing forward.
	- The minimum distance the sensor can measure is about 5 cm, so don't mount it right at the very front of the robot. Mount it far enough back that it is still more than 5 cm from the barrier when the front of the robot is 1 cm away.
	- Measure the distance from the face of the sensor to the front edge of the robot. You will need this number to set your target.
2. Plug the sensor into an I2C port on the Control Hub and add it to your robot configuration on the Driver Hub.
3. Learn how to read the sensor by studying the **SensorREV2mDistance** class in the **external.samples** package in Android Studio.
### Create the OpMode
1. In your **auto** package, create a new class named `YourNameDistancePIDTest`.
2. Make sure your class extends `LinearOpMode` and follows the structure of your other autonomous OpModes:
```java
@Configurable
@Autonomous(name="Your Name: Distance PID Test")
public class YourNameDistancePIDTest extends LinearOpMode {

}
```
1. Complete the OpMode so that the robot uses the output of your PIDF class to drive toward a barrier and stop 1 cm before hitting it. Your code should:
	- Create a new PIDF controller by calling `distancePID = new PIDF(kp, ki, kd, kf, tolerance);`
	- Repeatedly call `distancePID.update(targetDistance, currentDistance);` inside of a `while (opModeIsActive()) {}` loop, and use the returned value to set the power of your drive motors.
	- Use telemetry to display the current distance, the error, and the output on every pass through the loop.
<callout icon="💡" color="gray_bg">
	**Things to think about**
	- **What is the target?** The sensor measures the distance from the sensor, not from the front of the robot. If the sensor is mounted back from the front edge, what reading means the front of the robot is 1 cm from the barrier?
	- **Which way is forward?** When the robot is far from the barrier, the current distance is larger than the target, so the error is negative. Check whether a negative output should drive your robot forward or backward, and flip the sign if you need to.
</callout>
### Tune the Controller
To tune your gains without re-uploading your code every time, declare them as `public static` variables at the top of your OpMode, just like `TICKS_PER_CM` in <mention-page url="https://app.notion.com/p/3e8ec788f84081bfb04fc5fa0e9c07fe"/>. Pass them into the `PIDF` constructor.
```java
public static double KP = 0.0;
public static double KI = 0.0;
public static double KD = 0.0;
public static double KF = 0.0;
public static double TOLERANCE = 0.5;
```
Because the constructor copies these values when the OpMode initializes, you need to stop and re-initialize the OpMode after changing them in Panels.
Tune one gain at a time:
1. Start with only `KP`. Increase it until the robot reaches the target quickly but starts to overshoot or oscillate.
2. Add `KD` to damp the overshoot.
3. If the robot stops short of the target, add a small `KI` or `KF` to close the gap.
Record each set of gains you try, and what the robot did, in your engineering notebook.
